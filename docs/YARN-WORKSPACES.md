# Bounded Yarn workspace inventory · Issue #3 / M1

ArkCompat now inventories safe Yarn workspaces selected by root
`package.json.workspaces`. It projects a module-local dependency graph from the
selected root `yarn.lock` without loading Yarn configuration or plugins,
installing packages, executing lifecycle scripts, reading `node_modules`, or
following workspace symlinks.

```sh
node apps/cli/dist/index.js scan \
  fixtures/developer/yarn-workspaces \
  --runtime arkts --release 6.0.0 --api-level 20
```

## Discovery boundaries

- The root workspace value follows npm/Yarn's array or
  `{ "packages": string[] }` shape. Nonempty strings are required; malformed
  data aborts.
- Shared discovery accepts exact safe path parts, single-segment `*` and
  zero-or-more-segment `**` patterns. It normalizes one leading `./`, rejects
  traversal, absolute/URL-like patterns, unsupported glob syntax, symlinks and
  excluded directories, and stops at 128 selected workspaces. Wildcard traversal
  shares a 4,096-directory read budget; a terminal globstar selects directories
  containing `package.json`.
- Each selected manifest must be a regular, non-symlink `package.json` within
  the shared file and total-byte limits. Duplicate names, missing
  names/versions and unavailable manifests remain `declarations-only` with an
  explicit limitation.
- The selected workspace's declarations are preserved with safe public
  specifiers. Each becomes an `inventory.dependency` finding at its actual
  manifest line and column. The workspace manifest is not reported as a nested
  unselected manifest.

## Classic v1 projection

Yarn Classic does not record the workspace projects or their importer metadata
in `yarn.lock`. The adapter therefore projects only exact registry descriptors
that are already present in the validated lock graph. It never guesses that a
matching package name or a semver range means a local workspace link.

An external declared descriptor can receive `locked` coverage and its recorded
transitive edges. A dependency naming a selected workspace remains
`unsupported` with `yarn-classic-workspace-link-not-recorded`. Missing and
peer descriptors remain `missing` or `unsupported`; dev dependencies can have a
descriptor edge, while peer/hoisting resolution is not evaluated.

## Berry v8 workspace descriptors

The parser validates every grouped selector and records only safe
`name@workspace:path` entries with matching install identity and `linkType:
soft`. Resolution paths must be normalized in-tree paths. Workspace build
metadata is not reinterpreted as registry `optional` metadata.

A selected manifest receives `kind: "yarn"` and
`yarn-berry-lockfile-partial` coverage only when:

- its lock resolution path and selector names match the manifest name;
- the manifest has a nonempty version;
- regular and optional declarations in the lock workspace entry match the
  manifest after accepting Yarn's `npm:` registry prefix normalization; and
- the resolved workspace path is one of the safely selected manifests.

The module node uses the manifest's version and a stable
`yarn-berry-workspace:<relative-path>` ID with `link: true`; it does not
pretend that Yarn's `0.0.0-use.local` lock placeholder is a published version.
Workspace-to-workspace descriptor edges then continue through the target
manifest and registry transitives. Cycles are expanded once. Missing,
invalid, stale or unselected workspace entries stay `declarations-only` with
specific limitations.

The root graph still omits workspace protocol internals, so
`yarn-berry-root-workspace-links-not-resolved` remains visible there. The
module-local graphs resolve only exact recorded workspace descriptors.

## Contract and limits

Schema `0.12.0` retains `kind: "yarn"` and adds explicit semver `mismatch`
within Classic/Berry module projections. Historical Schema0.11 reports remain
historical artifacts; rebuild strict Web/VS Code consumers and rescan rather
than editing a version field.

All module graphs are inventory evidence, not installation, PnP/hoisting,
tag/non-semver/peer or runtime compatibility proof. URLs and private patch,
portal, exec and virtual locators never enter public IDs. Yarn configuration,
plugins, releases, `.pnp` state, scripts and packages are never loaded or
executed. Compatibility remains `not-evaluated` until reviewed rules and
knowledge are explicitly supplied.
